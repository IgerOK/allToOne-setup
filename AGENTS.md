# AGENTS.md — протокол контекста проекта AllToOne

Этот файл читает любой LLM-агент (Agnes, Claude, Cursor, Copilot), работающий в этом репо.
Он описывает систему переноса контекста между чатами/агентами.

## Модель: три файла + пакет

| Файл | Роль | Лимит |
|------|------|-------|
| `context/state.json` | Текущее состояние: цель, файлы, TODO, resume_log | ≤ 1.5KB |
| `context/decisions-active.md` | Журнал решений, активные 5 записей | ≤ 2KB |
| `context/open-questions.md` | Открытые вопросы | ≤ 0.5KB |
| `handoff.md` (корень) | Однофайловый пакет для переноса в другой чат/агент | ≤ 5KB |

**Горячие файлы — plain, компактные.** Это всё, что грузится в новый чат (~4KB, ~1000-1200 токенов).
**Аудит и история — git.** Архива нет: `git log -p <файл>` заменяет gzip-архивы.

## Триггеры записи

### Тихая запись (без диалога с пользователем)
При любом из событий агент сразу обновляет горячие файлы:

- принято значимое решение → append в `context/decisions-active.md`
- создан/изменён файл, важный для понимания проекта → обновить `files[]` в `state.json`
- сменён план/TODO → обновить `goal`/`todo` в `state.json`
- возник/закрыт открытый вопрос → обновить `context/open-questions.md`

Каждая тихая запись инкрементирует `version` в `state.json` и обновляет `updated`.

### Автономный цикл перехода (без вмешательства пользователя)

**Принцип: transition инициирует любой из двух — агент (страховка) или пользователь (по индикатору).**

- **Пользовательский триггер (75% индикатора):** увидев 75% заполнения контекста, пользователь предлагает открыть новый чат — pack + перенос + unpack агент делает сам. Это основной, самый ранний путь; ground truth = индикатор токенов пользователя, инициатива за пользователем.
- **Напоминание агента (~85% контекста, страховка):** если пользователь не инициировал до 85%, агент сообщает: «контекст близок к порогу, предлагаю открыть новый чат — пакет уже готов / сейчас соберу» (pack при необходимости, тихо). Порог — эвристика: агент не может точно измерить собственное заполнение контекста; ground truth — индикатор токенов пользователя. Досрочное напоминание допустимо, но agent обязан признать, что оценил на глаз.
- **Ответ на напоминание — у пользователя:** либо соглашается, либо цитирует индикатор (например, «39/473»). Агент действует по индикатору, не по своей оценке: далеко от 75% → продолжить в этом чате; ≥75% → pack + переход в новый чат.
- **Pack (~95% или по решению выше):** полный pack-коммит `ctx: v{N}` до конца сессии.
- **Новый чат — автоматический unpack:** агент самого первого хода прочитывает `handoff.md` + `state.json`, проводит health-check, формулирует 3–5 строк и **предлагает начать**: «вот где мы / что дальше — идём?». Работа стартует после подтверждения («идём») — напоминание и unpack не разрушительны, подтверждение нужно только началу работы.
- Пользователь в идеале делает одно действие: по индикатору (~75%) открыть новый чат (или сказать «продолжи» — unpack тоже тихий).

Этап, где агент не напомнил/не предложил, а просто «умер» от compacting — дефект протокола, фиксируется в `resume_log` (ok=false, note).

### Pack («сохрани контекст» / порог ~95% контекста)
1. Пересобрать все 3 горячих файла (сверка актуальности)
2. Заполнить `handoff.md` по шаблону (см. ниже), `source: manual` или `source: auto-snapshot`
3. Записать одну строку в `resume_log` предыдущего развёртывания, если миссия закончена
4. Один коммит: `ctx: v{N}` — **`state.json` и `handoff.md` никогда не коммитятся вразнобой**

Если контекстное окно агента подходит к компакционному порогу (~85%): предупредить
пользователя и предложить начать новый чат. При ~95% — сделать pack до конца сессии.

### Триггеры Unpack (слова, которые запускают восстановление)

По умолчанию — любое из:

- **«продолжаем»**, **«продолжи»**, **«далее»** (вариативы: «продолжай», «продолжим», «дальше»)
- Пустой/приветственный первый ход в новом чате этой папки (агент сам предлагает unpack, если видит `AGENTS.md`)

**Пользователь может настроить свои триггеры:** в `state.json` поле `"unpack_triggers": [...]` (массив строк). Если поле заполнено — агент реагирует только на эти фразы; если пусто/нет — работает набор по умолчанию. Пример кастомизации:

```json
"unpack_triggers": ["го", "идём", "вперёд"]
```

Эта настройка — тихая запись (обновить `state.json` + lockstep `ctx: v{N}`), не разрушительное.

### Unpack (по триггеру или пустому первому ходу)

**Обязательный алгоритм (нет неопределённости):**

1. Прочитать `handoff.md` (корень) + `context/state.json`.
2. Health-check (5 секунд): размеры в лимитах? lockstep? `files[]` существуют? TODO не устарели? Мелкая чистка несоответствий — в первом коммите сессии.
3. **Обязательно** сформулировать пользователю 3–5 строк: цель, ключевые решения, что в работе, открытые вопросы.
4. **Обязательно** закончить предложением: *«Где мы / что дальше — идём?»*
5. **Ждать явного подтверждения** («идём», «да», «старт»). Работа стартует **только после** подтверждения.

**Пустой/приветственный первый ход в папке, где есть `AGENTS.md`:**
Агент **всегда** выполняет шаги 1–5 автоматически (не молча стартует, не ждёт триггер). Это не разрушительно — unpack не изменяет файлы, только читает. Но **начало работы** всё равно ждёт «идём».

**Пустой чат в папке БЕЗ `AGENTS.md` (чужой/новый проект):**
Агент **не подхватывает чужие допущения молча**. Он не читает, не unpack'ит, не предлагает «продолжить». Ждёт команды пользователя. Если пользователь скажет «создай AllToOne для этого проекта» → агент инициализирует (см. ниже).

**Fallback: `AGENTS.md` есть, но `handoff.md`/`state.json` отсутствуют или несостоятельны (health-check FAIL):**
Агент НЕ выдумывает состояние. Сообщает коротко: «AllToOne-каркас есть, но L2-якорь отсутствует/несогласован — health-check FAIL». Предлагает одно: (а) восстановить из последнего чистого git-коммита L2 (`git log` + checkout), (б) инициализировать заново. Старт — только после выбора пользователя. «Тихо доделал сам» запрещён.

## Форматы

### `state.json` (контракт полей)
```json
{
  "project": "AllToOne",
  "version": 1,
  "updated": "ISO-8601 с таймзоной",
  "chat_ref": "идентификатор последнего активного чата/агента",
  "goal": "Одна строка: текущая цель (≤ 100 символов)",
  "files": [
    {"path": "src/x.py", "role": "одна строка: зачем файл"}
  ],
  "todo": ["пункт (≤ 15 на 20)", "..."],
  "resume_log": [
    {"v": 1, "chat": "идентификатор разворачивавшего агента", "ok": true, "note": "коротко: что получилось/запуталось"}
  ]
}
```
Лимиты: `goal` ≤ 100 симв., `files` ≤ 20 записей, `todo` ≤ 15 пунктов, `resume_log` ≤ 10 записей
(старые срезаются — история в git).

### `decisions-active.md`
Формат записи:
```
- [дата] РЕШЕНИЕ (одна строка) — почему (одна строка)
```
Максимум 5 раскрытых записей. При добавлении 6-й: старейшая закрывается
(переносится в заголовок `## Архив` одной строкой), раскрывается новая.
Полная история — `git log -p context/decisions-active.md`.

### `open-questions.md`
Формат:
```
- [дата] вопрос (одна строка) — статус: открыт / на паузе / решён
```
Решённые вопросы удаляются в коммите, где принято решение.

### `handoff.md` (пакет, шаблон)
```markdown
---
project: AllToOne
version: N
updated: ISO-8601
chat_ref: <идентификатор агента/чата>
source: manual | auto-snapshot
---

# Цель
<одна строка>

# Текущее состояние
- `путь/файла` — роль (готово / WIP ~% / …)

# Ключевые решения
| Что | Почему |
|-----|--------|

# TODO
- [ ] …

# Открытые вопросы
- …

# Уроки / не наступать на грабли
- …

# Как развернуть в новом агенте
1. Прочитай этот файл
2. Сверь `context/state.json` с этим файлом (health-check)
3. Прочитай файлы из `files[]` для ориентации
4. Начни с TODO[0]
5. В конце миссии добавь запись в `resume_log` (ok + note)
```

## Правила

- **Тихо писать, явно читать.** Тихая запись — без диалога. Загрузка в чужом чате — только по команде.
- **Операция = коммит.** Любая смена контекста коммитится: с кодом (в его коммите) или отдельно `ctx: v{N}`. Оптимизация/чистка — `ctx: optimize (...)`. Любой откат — `git revert`.
- **Верх по размеру.** Оптимизация обязана убирать больше, чем добавлять. Лимиты из таблицы обязательны.
- **Разрушительных действий без подтверждения нет.** Смена goal, удаление решения — только через вопрос пользователю.
- **Индикатор — ground truth.** На напоминание агента о переходе пользователь отвечает: (а) «да» → pack + переход; (б) цитирует индикатор (например, «39/473») → агент следует индикатору: < 75% продолжаем, ≥ 75% → pack + переход. Оценка агента на глаз не перебивает индикатор.
  - **Компактный формат:** пользователь может периодически скидывать индикатор без пояснений в виде `NN/NNN` (например, `47/465`). Агент распознаёт это как сырой индикатор и сразу действует по числам: < 75% → подтверждаю «продолжаем здесь», ≥ 75% → pack + предлагаю переход. Никакого разбора не требуется — только короткое подтверждение и действие.
- **`resume_log` — обязанность.** Если миссия завершена (или pack) — агент, который разворачивался, отмечает, получилось ли у него стартовать и с чего пошёл сбой.
- **Cross-agent.** Все файлы plain, секции на русском, ключи JSON в английских нижних-кейсах. Файлы читаются любым LLM-агентом и человеком без LLM.

## v2: Оптимизатор контекста (спецификация зафиксирована 2026-10-24; регистрация — по подтверждению)

Одна scheduled task (new_session, project_dir = этот репо) выполняет 3 модуля.
Принцип: **разрушительных действий без подтверждения нет** — неразрушительное автокоммитится, разрушительное — только вопросом.

### Модуль 1 — Drift-детектор
Сверяет `state.json` ↔ `handoff.md`: version/goal/todo/`files[]` согласованы; `decisions-active.md` — активны ≤5; лимиты размеров (1.5/2/0.5/5 KB). Вывод: список дрейфов.

### Модуль 2 — Cleaner (неразрушительное, тихо)
- Файл > лимита → сжатие без потери смыслов, коммит `ctx: optimize (...)`
- >5 активных решений → старейшие сворачиваются в `## Архив` (по одной строке)
- Устаревшие TODO/вопросы → удаляются (история — в git)
- Нечего делать → **без коммита**: не бампить version ради appearances

### Модуль 3 — Guardian (разрушительное — только вопросом)
Смена `goal`, отмена решения, переписывание ролей `files[]` → кандидаты выносятся пользователю; применяются только после подтверждения.

### Prompt задачи (для scheduled task)
«Прочитай `handoff.md` + `context/state.json`, пройди health-check протокола: лимиты, `files[]`, TODO, ≤5 активных решений.
Если есть дрейф: выполни Cleaner (автокоммит `ctx: optimize`); где нужен Guardian — вынеси список вопросов в сессию.
В конце — запись в `resume_log`: {v, chat: "optimizer", ok, note}».

Регистрация: еженедельно или вручную после 5–10 развёрток (ждёт подтверждения пользователя).

## Цикл развёртки (deploy checklist)

Операционный чек-лист E2E-развёртки (сценарий 3). Введено в тест-цикле 10/10 (2026-10-25).
`AGENTS.md` — живой документ: уроки развёрток эволюционируют эту секцию (по принципу «оптимизатор + уроки», цель 2).

- **Развёртка на git-ветках:** две ветки `chat-A`/`chat-B` расходятся от одного base-коммита; каждая = «сессия» (unpack → работа → pack).
- **Lockstep:** `state.json` и `handoff.md` — только в одном коммите.
- **Size-check ПЕРЕД pack:** сверить 4 hot-файла с лимитами (1.5/2/0.5/5 KB); если любой OVER — сначала сжать, не фиксировать OVER pack'ом.
- **Merge = семантический union:** сливать смыслы (resume_log / вопросы / решения), не `git --ours/--theirs`; потеря смыслов = дефект.
- **resume_log = 1 запись на сценарий** в merge (история = git, не копирование).
- **Health-check ПОСЛЕ merge (обязателен):** лимиты, version-lockstep, resume_log, `files[]`, ≤5 активных решений, чистый git.
- **>5 активных решений → архив:** старейшая сворачивается в `## Архив` одной строкой.
- **Разрушительное — только вопросом:** смена goal, отмена решения, переписывание ролей `files[]`, изменение cron → кандидат Guardian, применение после подтверждения; подтверждённое — отдельным коммитом (не смешивать с `ctx: v{N}`).
- **2 смежных решения концентрировать в 1** (меньше архива).
- **Цикл 5–10 развёрток** — обязательный proof self-развития перед регистрацией/оптимизацией v2.
## Инициализация AllToOne для нового проекта (по команде пользователя)

Пока пользователь не инициализировал проект, AllToOne к нему **не применяется**. Триггер — явная команда: «создай AllToOne для этого проекта», «примени протокол» и т.п.

Агент (одним ходом, тихо):
1. Создаёт `context/` + 3 файла (шаблон из §«Форматы»): `state.json` (v1, `unpack_triggers: []`), `decisions-active.md`, `open-questions.md`.
2. Создаёт `handoff.md` (шаблон, v1, lockstep с `state.json`).
3. Создаёт `AGENTS.md` (этот протокол + «Отношение к глобальным правилам» + «Цикл развёртки» — как в этом репо).
4. Создаёт `.gitignore` (`.agnes/`, системное).
5. **Если в папке уже есть файлы** (проект не пустой): беглый скан структуры (только верхний уровень дерева) → заполняет `files[]` (≤20 ключевых, роль в одну строку) и `goal` из увиденного. Чужие решения/планы из файлов в `decisions-active.md` НЕ переносятся автоматически — только факт структуры.
6. Первый коммит: `ctx: v1` — **все файлы в одном коммите** (lockstep).
7. Отчёт пользователю одной строкой: «AllToOne инициализирован (v1), цель: [заполнено из скана] — идём?» Работа стартует после подтверждения.

После этого проект ведётся по протоколу (тихие записи, pack/unpack, триггеры).

## Отношение к глобальным правилам (project override)

Этот репо переопределяет часть глобального канона (rules-Agnes) для целей cross-machine handoff.

- **L1 (локальный WIP):** .agnes/session-state.json (rules §7) — вспомогательный, ТОЛЬКО эта машина/чат, untracked.
- **L2 (handoff ground truth этого репо):** git-lockstep-пакет context/state.json + handoff.md (всегда в одном коммите).
- При L2-переносе (новый чат, смена модели, другая машина через GitHub) восстановление — СТРОГО из git, НЕ из .agnes/.
- Инвариант H1 (session-state.json — единственный source of truth) scoped на L1; для cross-machine handoff этот репо определяет L2 выше.
